2. Test Case Classification Matrix

The test cases are structured across the six mandatory IA3 categories: 1. Category 1 — Positive Testing (TC-POS-xx): Valid inputs and expected successful operations. 2. Category 2 — Negative Testing (TC-NEG-xx): Invalid inputs, corrupted artifacts, and unexpected conditions. 3. Category 3 — Boundary Testing (TC-BND-xx): Minimum, maximum, and edge-case limits. 4. Category 4 — Functional Testing (TC-FNC-xx): Verification of major features, explainability, and workflows. 5. Category 5 — Integration Testing (TC-INT-xx): End-to-end multi-tier communication across frontend, API, and engine. 6. Category 6 — Validation and Error Handling (TC-ERR-xx / TC-SEC-xx): Error messages, input restrictions, formula injection, and security invariants.

5. Summary of Defect Management & Resolution

During the IA3 verification audit, one critical routing defect was detected and resolved: - Defect ID: DEF-001 - Component: Next.js Frontend Routing (frontend/app/) - Severity: Medium (Usability / Navigation) - Description: When completing the Google OAuth flow or directly accessing deep links like http://localhost:3000/inbox, Next.js rendered its default 404: This page could not be found. because only the root / route was registered in the App Router. - Root Cause: Next.js App Router lacked dynamic segment handling for SPA tab paths. - Resolution: Implemented frontend/app/[tab]/page.tsx dynamic routing re-exporting the root application, and enhanced WorkspaceContext.tsx to inspect window.location.pathname upon initialization. - Verification: Verified with curl returning HTTP 200 OK on /inbox and /accounts. Next.js build passed with route ƒ /[tab]. All 157 automated tests remained 100% green.
